# 让测活反映真实使用

方案日期：2026-11-12。状态：历史产品建议与离线交互 Demo；其中的定向分组、测试来源标记和逐次请求展示等为拟议能力，不代表当前实现。实际行为以 [功能文档](../../.docs/db/features/realistic-probe.md) 和 [技术文档](../../.docs/tech/realistic-probe.md) 为准。

入口：[realistic-probe-demo.html](realistic-probe-demo.html)，可直接用浏览器打开。无需服务端、构建或网络。演示数据均为合成；不会重放生产日志、调用模型、保存输入或执行工具。

## 用户目标与取舍

用户明确目标：测活能够反映真实使用方式。

结合本次故障与管理台上下文，推断主要用户是接入、维护模型的管理员。他们要确认“我这个客户端请求能用吗”，失败后需要定位原因，而不是单纯查看一个绿色状态。此判断来自当前任务和代码，不是用户访谈结论。

语义发散后区分五个问题：

| 用户的问题 | 所需证据 | 本次建议 |
| --- | --- | --- |
| 凭据与服务是否能连接？ | 指定凭据的基础探测 | 保留现有诊断能力，不拆除 |
| 这个分组能处理我的请求吗？ | 客户端协议、请求形态、目标分组、最终上游请求 | 模型行测活默认验证这一层 |
| 应用经过网关后能完成吗？ | 真实身份、模型别名、正常路由、每次 attempt 与交付终态 | 单独提供客户端路由范围 |
| 工具、流式、多轮是否支持？ | 对应场景的请求与有效结果 | 使用场景模板，不把文本通过泛化为全能力通过 |
| 模型是真的、质量达标、长期稳定吗？ | 身份证据、任务评测、持续观察 | 不由本次测活承诺；不扩展成评测平台 |

不推荐只把 Responses 的字符串 input 换成列表就宣告目标完成：这是当前兼容问题的最小修复方向，但无法覆盖参数覆盖、流式、工具、授权和调度差异。不推荐在 probe 旁重写一套越来越复杂的“真实调用仿真器”：它会再次与真实请求路径分叉。

**推荐：保留基础诊断，增加共用真实数据面执行链路的测活工作区。** 简单用户用预填模板直接发起；复杂用户修改原始 JSON。无需新建测试配置平台、固定契约或能力矩阵数据库。

## 交互与执行方案

### 入口与默认值

- 模型行“测活”：建议默认当前分组，以现有 test_alias 定向。这是拟议变更，现有模型 probe 发送上游模型 ID。明确标记客户端模型名已替换，不将此结果称为原模型名请求的等价验证；要验证原请求，切换“客户端路由”。默认使用该入口适用的协议模板，明确流式状态。
- 调度中心：允许客户端原始模型名 / 别名，展示正常路由的候选与实际 attempts。
- 凭据“测试”：保留指定凭据诊断，不偷偷改成正常路由。成功恢复、失败不惩罚的既有语义仍可用，明确其验证范围。
- 初始模板无真实业务内容；Responses 用 user message 列表作为兼容性起点，不声称字符串违反官方协议。预算可编辑，不硬性复制 128 到所有推理模型。
- 本 Demo 只实现 Responses / Chat 交互；生产范围必须按数据面实际可用协议动态提供，不表示 Anthropic、Gemini、Embeddings、Rerank 被删除或已覆盖。

### 两种测试范围，一条执行链路

| 项目 | 当前分组 | 客户端路由 |
| --- | --- | --- |
| 模型键 | 当前条目的 test_alias | 用户真实模型 / 别名 |
| 身份 | 真实调用身份；无权限不发送 | 真实调用身份；无权限不发送 |
| 分组与凭据 | 限定条目，按正常调度约束选凭据 | 正常权限、路由与重试策略 |
| 参数、Headers、代理、超时 | 与实际请求使用同一准备逻辑 | 同左 |
| 按模型匹配参数规则 | 按 test_alias 匹配，可能不同于真实模型名 | 按客户端原始模型名匹配 |
| 结果 | 该分组在该请求下的结果 | 客户端最终结果 + 每条上游独立结果 |

test_alias 本身不是“只执行一次”的控制，也不会自动解除冷却、禁用或额度限制。访问密钥若配置模型过滤，必须允许这个 alias 本身，允许真实模型名不等于允许 alias。不能调用时应显示原因，例如分组禁用、条目零权重、条目 / 凭据冷却或黑名单、当前调度要求分组恰好一个凭据的约束；引导到明确的基础诊断 / 恢复操作，不自动放宽权限或绕过正常规则。Demo 为便于理解，合成环境设置每候选一次、最多两个候选；不是项目默认重试行为的复刻。

**复用真实链路不等于请求条件相同。** 覆盖规则会用客户端模型名匹配精确名 / 前缀；test_alias 与真实模型名可能命中不同规则。Demo 的“别名与覆盖”情境展示此差异：示例 `model=coding` 将输出预算覆盖为 512，test_alias 不命中而保留 1024。结果展示实际命中规则；若未来需要“保留原始模型名并锁定分组”，必须另行设计受权限约束的目标选择，不能假装现有 test_alias 已满足，也不应偷偷改变授权或规则匹配。当前建议把定向诊断与客户端路径验证分开。

落地应复用 gateway 的授权、路由、请求准备、执行、判决与记录实现，而非再次手工组装探测请求。管理台发起测试仍需要明确的调用身份；不得用管理员权限替代客户端访问范围。具体会话到调用身份的安全接口需要实现时设计，Demo 下拉框不是现有 API。

### 请求与可见证据

- 请求 JSON 是请求体的来源；协议、流式与模型字段需同步，不显示一套配置却发送另一套内容。改变协议会生成该协议的新模板，不能静默丢弃用户编辑；Demo 在已有自定义 JSON 时确认替换。
- 默认应用已保存分组参数，不为了通过测试绕过覆盖。测试前可以预览配置，但标明不是执行事实；发送后展示每个 attempt 的最终请求差异。
- 保留工具定义与多轮历史；只验证模型输出，不自动调用工具。原始 JSON 不等同完整客户端复现，动态 Header、SDK 重试、工具循环仍可能不同。
- 按真实数据面正常计量、额度与健康规则处理；保留真实请求的 operation，另设测试来源标记供筛选。不能复用会排除 usage 聚合的 `OperationProbe`。来源标记及接口仍待设计，不绕过扣费、限流或健康规则。开始前明确可能产生上游费用。
- 停止代表不发起后续尝试并请求取消当前执行，不保证上游没有收到或没有收费。现有批量 probe 的“停止后续批次”不等同单次请求取消；生产中需分别表达。

### 结果判定

1. 非流式：完整响应体、协议结构及终态有效，才能判定本次请求完成。
2. 流式：展示首个有效输出、总耗时、协议终态；200、连接成功或单个 delta 不构成通过。首个有效输出并不总是文本 token，工具参数也属于有效输出；指标命名避免混淆。
3. 工具请求：结构有效可以通过工具兼容性验证，即使没有可见文本。明确工具未执行、任务未闭环；生产应校验实际声明的 schema，不仅检查是否有 name。
4. 回退：第一上游失败、第二上游成功，客户端可以完成，但第一上游不能被标绿。内容已提交后的断流不能拼接另一上游响应来制造成功。
5. 无权限、无路由：未到达上游，不能说模型失败。
6. 取消、断流、缺终态：未完成，不等于模型永久不可用。
7. 结果附带请求条件和时间，不直接改为永久的模型能力标签，也不自动启用分组。

## 范围、风险与低成本验证

优先完成一个生成协议端到端切片及共享执行路径，再按现有协议能力扩展 UI。此顺序是交付切片，不是临时架构：最终仍共用真实 gateway，不保留两套复制的运行逻辑。

- **本期必要**：入口默认值、协议适配模板 / JSON、调用身份、定向与路由范围、普通参数处理、流式有效终态、独立 attempt 结果、请求日志关联、费用 / 状态影响提示。
- **后续有证据再做**：从日志创建请求草稿。必须存在完整可读原文、权限与脱敏确认；缺捕获就明确不可还原。禁止自动带入 Authorization、Cookie、凭据和敏感业务文本，更不能从结构化统计拼出“原请求”。
- **不做**：自动执行函数工具、模型身份担保、自动修改生产参数以使测试通过、全协议批量组合探测、自动调优、额外配置层或评测平台。
- **主要风险**：真实路径会影响额度 / 健康；原文可能有秘密；可复制请求仍不覆盖动态客户端行为；单次成功没有统计稳定性保证。UI 不能用“零副作用”“完全复现”掩盖这些差异。

先让维护者操作本 Demo：是否能分别解释“test_alias 不等价于原模型名的参数覆盖”“当前分组失败但客户端成功”“200 但流未完成”“工具输出无文本但结构有效”“日志没有原文不能重放”。如果只能看颜色猜结论，先修交互而不是加更多设置。

生产实现时，以脱敏请求和可控上游验证：

1. 相同调用身份、协议、别名、body 与已保存配置，在真实客户端与测活入口产生等价的上游请求；逐 attempt 对比，允许请求 ID / 时间不同。
2. 列表 / 字符串 input、分组覆盖、别名权限、禁用或冷却、503 回退、流中断、有效 tool call、取消均有可控证据；不依赖现场付费服务作为唯一测试。
3. 真实客户端做最后一轮验证，尤其是动态 Headers、SDK 流式解析与工具循环；不得用 Demo 模拟结果代替。
4. 校验计量、额度、健康更新与正常请求一致；单独筛选测试来源；capture 缺失不会伪造证据。

## Demo 边界

HTML 中的 `ProbeLogic` 是纯内存演示状态机，独立于 DOM。UI 通过定时推进或“执行下一步”调用它；所有服务响应、规则与延迟是合成值。请求校验仅够支持本 Demo，不是完整 JSON Schema 校验或生产协议实现。没有外部字体、脚本、框架、数据库或存储。

视觉沿用 Astryx 的浅色中性底、深蓝动作色、系统字体、紧凑控件与分区层次。工作区扩展原测活流程，逻辑与竞品说明仅是方案演示视图，不建议作为产品新增一级页面。
