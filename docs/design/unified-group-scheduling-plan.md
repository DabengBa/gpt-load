# 统一分组与模型调度开发计划

## 1. 目标

将“分组”和“调度中心”统一为一套模型路由管理系统，消除重复权重、重复保存、功能冲突和页面往返跳转。

最终产品规则：

- 一个分组只拥有一个上游凭据（API Key 或订阅账号）。
- 删除分组权重。
- 删除凭据权重。
- 模型条目权重、优先级和模型级熔断参数只由调度中心维护。
- 分组页只维护分组资源和模型结构。
- 凭据 Secret 只在分组凭据区域维护。
- 调度中心展示跨分组的最终候选，但不复制分组和凭据配置。
- 不保留旧的多 Key、多层权重或旧编辑入口兼容层。

## 2. 最终领域模型

```text
Group
  ├── connection settings
  ├── one Credential
  └── Route Entries
        ├── entry_id
        ├── upstream model id
        ├── alias
        ├── weight
        ├── priority
        └── circuit breaker override
```

访问密钥是客户端请求上下文，不属于上游分组资源：

```text
AccessKey + Protocol + Operation + ExternalModel
  -> candidate Route Entries
```

### 2.1 唯一字段归属

| 字段或行为 | 唯一维护位置 | 说明 |
|---|---|---|
| 分组名称、渠道、连接类型、代理 | 分组设置 | 资源本身配置 |
| 分组启停 | 分组设置 | 禁用整个上游分组 |
| 模型 ID、别名、增删、同步 | 分组模型 | 维护模型结构 |
| 模型条目权重 | 调度中心 | 只影响该模型候选 |
| 模型条目优先级 | 调度中心 | 只影响该模型候选层级 |
| 模型级熔断参数 | 调度中心 | 只影响该模型条目运行态 |
| API Key/订阅授权、Secret | 分组凭据 | 一个分组只有一个 |
| 凭据启停 | 分组凭据 | 禁用该分组的上游认证 |
| 凭据测试、刷新、恢复 | 分组凭据 | 凭据级运行态 |
| 客户端访问密钥 | 访问密钥页 | 客户端认证和授权 |

## 3. 调度计算模型

删除分组权重和凭据权重后的候选计算：

```text
候选有效质量 = RouteEntry.weight × CredentialAvailability
```

其中：

- `RouteEntry.weight` 是调度中心维护的模型候选权重。
- `CredentialAvailability` 是单一凭据的可用性，不再是可配置权重。
- 分组 `enabled=false`、凭据 `status=disabled`、凭据运行态不可用时，候选直接被排除。
- `priority` 先决定当前生效层级，再在该层按条目权重分配。
- 一个分组只有一个 Key，因此不存在组内 Key 之间的二次加权和 Key 级负载分配。

示例：

```text
external model: gpt-4o

Group A / entry A: priority=1, weight=70, credential available
Group B / entry B: priority=1, weight=30, credential available
Group C / entry C: priority=2, weight=100, credential available

P1 生效时：A=70%，B=30%，C=0%
A、B 都不可用时：P2 生效，C=100%
```

调度中心显示分组和凭据状态作为只读事实，但不再把它们乘进可编辑权重公式。

## 4. 页面结构

### 4.1 分组页

```text
分组详情
├── 概览/设置
├── 模型
└── 凭据
```

#### 设置区域

保留：

- 分组名称
- 渠道和连接类型
- 分组启停
- 代理
- 超时、重试和其他分组运行参数

删除：

- `weight_manual`
- `group_weight`
- 所有“分组权重”文案、表单、DTO 和缓存字段

#### 模型区域

负责：

- 新增模型
- 删除模型
- 同步模型
- 修改上游模型 ID
- 修改别名
- 展示条目权重、优先级、熔断配置和运行态
- 提供“在调度中心查看”入口

不负责直接保存调度参数。模型列表中的调度字段使用只读展示；编辑按钮打开共享的调度编辑器，并携带当前模型上下文，不跳转到另一个独立编辑页面。

模型结构变更与调度参数变更分开提交：

- 模型结构：分组模型 API。
- 调度参数：调度中心 API。

模型结构保存必须完整保留 `entry_id` 和 `circuit_breaker`，但不再通过分组页重复编辑调度参数。

#### 凭据区域

一个分组只能有一个凭据区域，负责：

- 创建或导入一个 API Key/订阅账号
- 替换现有凭据
- 删除凭据
- 启用或停用凭据
- reveal/download
- 测试、刷新、重新授权和恢复
- 配置凭据级代理（如果仍有必要）
- 展示凭据运行态

删除：

- `weight_manual`
- 自动凭据权重
- 凭据权重模式
- 多 Key 批量选择、批量权重和 Key 之间的流量分配文案

单凭据的唯一维护入口为“管理”：首次导入、替换、刷新、重新授权和删除都在该入口完成；不再拆分“替换”与“管理”，也不提供多凭据列表操作。

### 4.2 调度中心

调度中心是跨分组的模型路由操作台：

```text
调度中心
├── 对外模型索引
└── 模型候选详情
    ├── 分组信息
    ├── 模型条目参数
    ├── 凭据可用状态
    ├── 实时运行态
    └── 最终有效占比
```

可编辑：

- 条目权重
- 条目优先级
- 模型级黑名单阈值
- 模型级冷却时间
- 模型条目恢复

只读：

- 分组名称和渠道
- 分组启停状态
- 单一凭据可用状态
- 凭据错误原因
- 当前最终有效占比
- 配置来源和运行态

不提供：

- 分组权重
- 凭据权重
- Secret 编辑
- 分组全量设置编辑
- 凭据恢复
- 访问密钥授权编辑

## 5. 交互方案

### 5.1 共享编辑器

新增或整理为共享组件：

- `ScheduleEntryEditor`：编辑条目权重、优先级、熔断参数。
- `RouteCandidateFacts`：展示分组状态、凭据状态、运行态和最终占比。
- `ResourceContextDrawer`：从调度中心查看分组设置或凭据详情，保留原调度上下文。

调度中心和分组模型页不各自实现一套字段编辑逻辑。

### 5.2 无页面往返

从调度中心查看上游资源时：

1. 优先打开侧栏或嵌套抽屉。
2. 保留 `external_model`、`group_id`、`entry_id` 和当前行/草稿上下文；协议、操作和访问密钥由当前请求或系统默认上下文在后台解析，不作为页面导航状态。
3. 关闭后恢复原调度详情、草稿和滚动位置。
4. 只有需要完整资源管理时才进入分组页。
5. 返回调度中心时恢复完整上下文，不回到默认索引。

从分组模型页进入调度中心时，直接携带模型和分组上下文，不要求用户先触发额外 GET 来解决内部身份问题。

### 5.3 运行态操作分层

| 问题 | 唯一处理位置 |
|---|---|
| 模型不可用、模型条目冷却或拉黑 | 调度中心 |
| Key 无效、Key 冷却或订阅授权过期 | 分组凭据 |
| 分组被管理员停用 | 分组设置 |
| 客户端访问密钥被停用 | 访问密钥页 |

调度中心可以显示凭据问题，但不能用模型条目“恢复”按钮伪装恢复凭据。

## 6. 后端契约调整

### 6.1 存储和状态

删除以下字段及其状态传播：

- `models.Group.WeightManual`
- `models.Credential.WeightManual`
- `state.GroupView.WeightManual`
- `state.CredentialMeta.WeightManual`
- `state.CredentialEntry.WeightManual`
- 相关 `WeightAuto`、权重模式和组/凭据权重派生逻辑

分组凭据关系改为单值关系。服务层在创建、导入、替换和删除操作中保证一个分组最多一个凭据；超过单凭据约束的数据视为无效状态，不设计兼容读取或多 Key fallback。

保留：

- 模型配置中的 `entry_id`
- 模型配置中的 `weight`
- 模型配置中的 `priority`
- 模型配置中的 `circuit_breaker`
- 凭据的启用状态和运行态

### 6.2 调度器

修改 `internal/scheduler/`：

- 删除 group weight 和 credential weight 参与候选质量计算的参数。
- 删除 `group_weight_zero` 和 `credential_weight_zero` 原因码。
- 保留分组禁用、凭据禁用和凭据运行态不可用原因码。
- 候选池按 entry weight 和 priority 计算。
- 单 Key 直接作为分组候选的认证来源，不再建立 Key 权重池。
- 更新路由检查、真实转发和调度中心使用的同一计算内核。

### 6.3 管理 API

删除：

- 分组设置 API 中的 `weight_manual`。
- 凭据详情和更新 API 中的 `weight_manual`。
- 调度详情响应中的 `group_weight`。
- 调度详情响应中的凭据权重字段。
- 相关三态 PATCH 逻辑。

保留并收敛：

```text
PATCH /api/model-route/schedule
{
  snapshot_revision,
  updates: [
    {
      group_id,
      entry_id,
      weight?,
      priority?,
      circuit_breaker?
    }
  ]
}
```

该接口是模型条目调度字段的唯一写入口。

凭据 API 只保留单凭据的 Secret、状态、代理和生命周期操作。

## 7. 前端资源和缓存调整

### 7.1 删除资源字段

清理：

- `groups.ts` 中的分组权重 DTO、投影和请求字段。
- `credentials.ts` 中的凭据权重 DTO、patch 和投影字段。
- `model-route-schedule.ts` 中的 `group_weight` 和凭据权重投影。
- `route-inspection.ts` 中的组/凭据权重展示字段和原因码。
- 分组设置、模型页、凭据页和调度中心中的对应国际化文案。

### 7.2 缓存失效

所有影响候选可用性的变更继续统一失效调度资源：

- 分组启停或连接设置变更。
- 模型新增、删除、别名或上游模型 ID 变更。
- 单一凭据新增、替换、删除、启停、刷新或恢复。
- 调度中心条目参数保存或恢复。
- 访问密钥授权范围变更。

删除仅为权重字段存在而建立的额外缓存分支，所有 mutation 仍通过 `applyInvalidationPlan()` 执行。

## 8. `entry_id` 处理

`entry_id` 是模型条目的稳定身份，必须在调度管理 API 返回前完成准备。

实施要求：

- 创建、导入、同步时直接生成真实 `entry_id`。
- 读取旧数据时由后端完成一次性持久化补全。
- 调度中心管理 API 不返回可编辑的 `derived:` 条目。
- 回填失败时返回明确的数据完整性错误，不把临时身份暴露为用户工作流。
- 前端删除所有“去模型页触发回填后才能编辑”的流程。
- PATCH 和恢复始终使用真实 `(group_id, entry_id)`。

## 9. 实施阶段

### S1：契约和调用图盘点

- 全局列出 group weight、credential weight 的所有读写、计算、API、测试和文案。
- 识别仍依赖多凭据的业务路径。
- 确认调度、路由检查、真实转发共享的候选计算入口。
- 输出删除清单和新 DTO 清单。

验收：没有遗漏的生产代码读写点；所有字段都有唯一处理结论。

### S2：领域模型和调度器收敛

- 删除 Group/Credential/State 的权重字段。
- 将分组凭据改为单凭据语义。
- 修改 scheduler、inspect、snapshot、loader 和 runtime registry。
- 删除组/凭据权重原因码和计算分支。
- 先通过编译，再运行调度和路由检查回归测试。

验收：同一模型的跨分组分配只由 entry weight、priority 和可用性决定。

### S3：后端 API 收敛

- 删除分组设置和凭据 API 的权重字段。
- 删除调度响应中的 group weight 和 credential weight。
- 保留模型条目调度 PATCH 和恢复接口。
- 收敛单凭据创建、替换、删除和状态操作。
- 更新审计定位和错误码。

验收：旧字段不会被接受、写入或回显；不存在第二个调度权重写入口。

### S4：前端页面合并

- 分组设置删除分组权重。
- 分组模型页改为结构维护和只读调度事实展示。
- 凭据页改为单凭据维护，删除凭据权重和多 Key 批量交互。
- 调度中心只编辑条目调度参数。
- 引入共享编辑器和上下文抽屉。
- 清理三套 locale。

验收：常见工作流不需要在分组、模型、凭据和调度中心之间反复跳转。

### S5：缓存、导航和运行态验收

- 完成所有 mutation 的调度缓存失效。
- 验证模型结构、凭据生命周期和调度编辑之间的即时一致性。
- 验证调度上下文前进、后退、刷新和深链恢复。
- 验证模型级恢复不会改变凭据运行态。
- 验证凭据恢复不会修改模型条目配置。

验收：页面显示、路由检查和真实请求使用同一候选结果。

### S6：全量验证

- Go 编译和全量测试。
- 前端类型检查、lint、格式检查和生产构建。
- 管理员和访问密钥两种身份的权限验证。
- 桌面端和 390px 移动端 Playwright 走查。
- 检查无横向溢出、无重复权重字段、无 `derived:` 可编辑行。

## 10. 验收场景

1. 创建一个分组并导入一个 Key；第二次创建/导入必须明确走替换或拒绝，不能形成第二个 Key。
2. 在调度中心修改模型候选权重，分组模型页只展示结果，不出现第二个编辑入口。
3. 删除或停用凭据后，调度中心候选立即变为不可用，但模型条目权重和优先级不变。
4. 修改分组启停后，调度中心候选立即排除或恢复，不产生任何隐式权重变化。
5. 调度中心保存模型级熔断参数后，分组模型页保存别名不会擦除该配置。
6. 同一对外模型跨三个分组时，最终占比只由条目权重、优先级和可用性决定。
7. 条目运行态恢复只清理条目级运行态；凭据恢复只清理凭据级运行态。
8. 任意旧数据缺少真实 `entry_id` 时，调度中心完成后端回填后直接可编辑，不需要用户跨页操作。

## 11. 明确不做

- 不保留分组权重作为隐藏 fallback。
- 不保留凭据权重作为自动默认值。
- 不通过 UI 禁用字段但继续在后端接受旧字段。
- 不让分组模型页和调度中心各自保存同一批调度字段。
- 不在调度中心复制 Secret 管理。
- 不增加新的兼容层、迁移命令或旧字段 fallback。
- 不修改既有 Go 路由策略的 priority、失败分类和 S1-S4 语义之外的行为；本计划只删除两层权重乘法和多凭据分流模型。

## 12. 已确认决策

1. 一个分组严格只允许一个上游凭据；再次导入或创建第二个 Key 直接拒绝，不做原子替换。
2. 删除凭据权重和凭据权重模式；单凭据不参与组内流量分配。
3. 删除凭据启停；只保留分组启停。凭据异常通过凭据生命周期、刷新、重新授权和恢复处理。
4. 删除凭据代理；只保留分组代理，作用于该分组的唯一凭据和上游请求。
5. 模型条目权重继续使用 `0–100`；`0` 表示保留条目但不参与分流。
6. 当前没有多凭据存量数据；删除旧权重字段，不设计多凭据兼容迁移或运行时 fallback。

## 13. UI 精简与单页维护决策

### 13.1 分组页面

分组基础信息、凭据和模型在同一页面维护。凭据操作统一为一个“管理”入口；该入口承载查看、导入/首次创建、替换、刷新、重新授权和删除，不同时出现“替换凭据”和“管理凭据”两个并列入口。

页面只展示用户需要决策的内容：

- 分组名称、渠道、连接类型和启停。
- 凭据的脱敏标识和可用性、授权/刷新问题。
- 模型名称、上游模型、条目权重和优先级的只读摘要。

不展示：

- `entry_id`。
- 分组内部 ID。
- 凭据内部 ID。
- 技术性快照 revision、身份 fingerprint、secret version。
- “凭据启用/停用”控件。

“当前状态”只表示分组状态；凭据只显示“可用/异常/需要重新授权”等健康事实，不再展示与分组状态并列的凭据开关。分组停用时，页面明确说明该分组及其唯一凭据都不会参与调度。

“分组代理、请求超时、失败重试”移动到页面底部的“高级配置”折叠区，默认收起。折叠区仍可编辑，但不在首屏制造调度概念噪音。

### 13.2 调度中心页面

调度中心采用类似 Excel 的紧凑表格，不使用大段解释、重复标题或每行重复事实。

固定列：

- 分组。
- 上游模型。
- 权重（可编辑）。
- 优先级（可编辑）。
- 当前占比。
- 状态。
- 模型级熔断摘要/恢复操作。

分组和凭据健康作为紧凑状态单元格展示；不展示内部 ID、Entry ID、凭据 ID、重复的“来源”说明和冗长解释。调度中心页面上方只保留对外模型选择，不提供协议、操作或访问密钥筛选。协议/操作仍由调用方和后端运行上下文决定，用于判定候选是否适用，但不参与候选优先级排序；访问密钥也不作为模型调度排序配置。

表格支持：固定表头、键盘/单元格编辑、批量草稿、统一保存、错误单元格定位和紧凑状态提示。详情信息通过悬浮提示或行展开提供，不改变主表密度。

## 14. UI 决策对应的代码逻辑变化

1. 分组页面路由取消凭据/模型/设置之间的 Tab 作为主要维护流程，改为单页组合查询；保留深链参数仅用于定位或展开对应区域，不创建第二套编辑页面。
2. 分组 API 的展示投影移除内部 ID、`entry_id`、fingerprint、secret version 等非用户字段；内部字段仍可在请求定位和服务端事务中使用，但不进入用户 DTO。
3. 分组状态成为唯一的 operator-controlled enable/disable 状态；Credential 模型删除 `Status` 及对应 handler、patch、DTO、缓存和运行时分支。凭据健康状态改为只读观察结果。
4. 分组设置 DTO 保留代理、超时和重试字段，但前端默认折叠；分组代理成为唯一代理配置来源，删除凭据代理覆盖和继承逻辑。
5. 调度详情 API 保留服务端定位所需的 `(group_id, entry_id)`，但前端资源层将其作为内部字段使用，不在表格展示；`PATCH` 和恢复仍由真实 `entry_id` 定位。
6. 调度中心前端从卡片/分组长列表改为扁平候选表格；保留 `snapshot_revision`、乐观并发、字段级 PATCH、409 和恢复逻辑，改为单元格级错误反馈。
7. 后端不得为了 UI 精简删除事务定位字段；安全投影和编辑请求继续严格校验未知字段，避免把“隐藏”误实现为“失去身份”。
8. 所有分组、模型和凭据变更继续失效调度缓存；单页组合查询不得引入重复请求。

## 15. 新增 UI 验收

1. 分组页面无 Tab；基础信息、凭据、模型和启停在一个页面可见。
2. 分组代理、请求超时、失败重试位于默认收起的高级配置中。
3. 页面不出现 Entry ID、分组 ID、凭据 ID、fingerprint 或 secret version。
4. 页面没有凭据独立启停开关；分组停用是唯一配置开关。
5. 分组状态与凭据健康状态语义不冲突，分别表达“是否参与调度”和“凭据是否健康”。
6. 调度中心首屏为紧凑表格，无重复长说明；权重和优先级可直接编辑。
7. 调度中心不显示 Entry ID、内部 ID 或重复来源字段。
8. 桌面和移动端表格可横向查看但不产生无意义的宽度溢出；键盘编辑、保存、409 和错误定位可用。
