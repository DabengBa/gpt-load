# 供应商管理原型方向卡

共同目标：让运营人员把多个独立分组归类到同一上游供应商，并查看归属、组数和组内凭据健康。归属仅用于管理，不改变每组独立凭据、组级调度或运行状态。原型中厂商名称、网址、备注、数量和状态均为演示数据。

## 方向 1：运营列表
- 逻辑与来源：从现有分组集合和密集表格出发，延续运维控制台的信息扫描方式。
- 借的是什么：固定列、清晰表头、细分割线；筛选和计数紧邻数据表。
- 主角素材：各供应商关联分组数与凭据健康汇总表。
- 骨架：页头操作、统计摘要、筛选栏、全宽供应商表格、未分配入口。
- 胆量花在哪：每行同时呈现供应商与跨分组健康，并明确这是分组状态汇总。
- form 来自内容的哪里：跨多个分组汇总的信息适合按行比较。

## 方向 2：目录与分组
- 逻辑与来源：按“先认供应商，再看它有哪些组”的浏览任务组织，采用轻量目录加详情面板。
- 借的是什么：目录与详情的稳定主从关系；卡片承载身份和摘要，明细保留在旁侧。
- 主角素材：供应商名、网址、备注及其分组列表。
- 骨架：供应商列表卡片加详情面板；移动端折叠为上下结构。
- 胆量花在哪：选择供应商后在同屏展开具体分组，减少详情页往返。
- form 来自内容的哪里：分组是供应商名下可直接跳转的工作对象。

## 方向 3：归属整理
- 逻辑与来源：优先解决增加供应商维度后的存量整理任务，以未分配分组作为工作队列。
- 借的是什么：批量操作列表、可见影响范围和逐行归属控件；归属操作与运行状态分开。
- 主角素材：未分配分组队列与归属选择器。
- 骨架：未分配说明、统计、分组表格、批量归属工具条、侧边详情。
- 胆量花在哪：将批量整理作为主要动作，而不是供应商资料浏览。
- form 来自内容的哪里：新维度启用后的首要现实工作是给现有分组补归属。

设计上下文：Astryx 运维控制台风格，浅色工作表面、紧凑导航、细边框、克制状态色、小圆角。状态同时用文字表达，不只依赖颜色；供应商标识使用字母缩写，不冒充真实品牌 logo。
