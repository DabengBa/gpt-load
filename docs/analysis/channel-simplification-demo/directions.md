# 渠道精简：六张方向卡

## 共同 spec

- 受众：配置上游的管理员；场景：探索如何减少渠道选择，同时保留现有功能边界。
- 问题：是否让常见场景先选择 OpenAI Compatible、输入演示配置和模型，并用有明确范围的模拟测活辅助判断？现有 OpenAI Compatible 默认指定模型 Chat 非流式测活；其他专用渠道使用各自探测预设，演示本身仅模拟 Chat 非流式。
- 交付：三个可独立打开的离线 HTML 初稿；横向比较基准为 1440×900，同样适配 375 宽。另有六格缩略备选和截图。
- 同一内容：连接类型、演示 Base URL、固定假 Key、手填模型、保存后模拟三种结果；明确建议/现状、云与多协议入口、既有组和旧库边界。
- 假设：面向管理控制面，而非面向终端用户；演示不是生产页面。交互全部在内存，刷新重置。
- 素材：T0，用表单、状态和表格结构作为主角；不使用品牌标志、外部图片或网络资源。
- 依据：`PRODUCT.md`、`DESIGN.md`、`.docs/db/pages/groups.md`、`.docs/db/features/realistic-probe.md`；产品现状与用户提供的需求不一致处，以项目现状文件为准并在页面标明。
- 离线限制：用户要求无需网络；未联网核实竞品或抓取现实参照截图。竞品行为仅作为用户提供的研究线索，不在页面中当作已核实事实，也不仿制其界面。
